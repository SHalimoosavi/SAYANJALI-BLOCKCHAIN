# SAYANJALI BLOCKCHAIN — Phase 5 Go Production Core

## Phase 5.1 remediation

This branch is the security/compatibility remediation for the original Phase 5 Go foundation. It does not redesign the frozen SYJ protocol.

### Canonical serialization

Protocol-critical values are encoded to reproduce the frozen Python behavior:

`json.dumps(payload, sort_keys=True, separators=(",", ":"), default=str)`

The Go serializer is self-contained and does not invoke Python at runtime. Supported protocol values are explicit concrete JSON primitives, arrays, and string-keyed objects. Unsupported Go types fail explicitly rather than relying on an incompatible `fmt.Sprint` fallback.

The compatibility suite includes a deterministic CPython oracle fixture generated by `tests/compatibility/generate_canonical_oracle.py`. It covers float boundaries, negative zero, exponent formatting, Unicode/ASCII escaping, control characters, nested objects/arrays, integers, booleans, null, and protocol-shaped payloads. The Go test compares serialized bytes exactly.

### Cryptography

Production secp256k1 arithmetic is delegated to:

`github.com/decred/dcrd/dcrec/secp256k1/v4 v4.4.1`

The dependency was selected because it is a mature, tagged, pure-Go secp256k1 implementation with specialized field/scalar arithmetic and a dedicated ECDSA package with extensive upstream tests. The library uses fixed-precision field/scalar primitives; this is not a claim that every operation in the library is constant-time. Its ECDSA package documents RFC6979 deterministic signing and canonical low-S signatures, while verification accepts valid ECDSA signatures without introducing a new high-S consensus rule.

The previous local `math/big` curve arithmetic has been removed from the production tree. SYJ-specific code is limited to protocol-boundary validation and conversion.

### Frozen SYJ key/signature representation

The protocol representation remains unchanged:

- Public key: raw `X || Y`, exactly 64 bytes; the SEC1 `0x04` prefix is used only as an internal conversion boundary for the vetted library.
- Signature: raw `R || S`, exactly 64 bytes; DER is not used on the SYJ wire/data boundary.
- Address: `SYJ` + first 40 hexadecimal characters of SHA-256(UTF-8(public-key-hex)).

The frozen transaction signature fixture remains normative. New Go signatures are deterministic because the selected library uses RFC6979; the protocol does not require byte-for-byte reproduction of Python's random nonce signatures.

The observed Python verifier accepts valid high-S ECDSA signatures, so this remediation does not add a low-S consensus restriction. New signatures are nevertheless canonical low-S as a library property.

### Adversarial crypto testing

Tests cover malformed and boundary private keys, malformed/off-curve public keys, zero/out-of-range signature components, corrupted signatures/messages/keys, deterministic signing, repeated verification, high-S compatibility, and a fuzz target for malformed public-key/signature input. Invalid external input must return false/error rather than panic.

### Monetary invariant hardening

`Supply.Apply` now checks `Total <= MaxSupplyBaseUnits` before subtracting from the cap. Invalid state cannot cause unsigned underflow, and failed applications do not mutate state. `IssueReward` also refuses invalid or exhausted supply states.

### Scope

This foundation intentionally excludes production P2P, RPC, storage, node lifecycle, public testnet, and consensus/tokenomics redesign. Phase 4 protocol specification and all frozen deterministic vector files remain unchanged.
