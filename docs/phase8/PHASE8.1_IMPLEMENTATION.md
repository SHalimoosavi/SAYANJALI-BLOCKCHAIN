# SYJ Blockchain Phase 8.1 — V2 Consensus Implementation

## Status

Phase 8.1 introduces a separate V2 consensus track while preserving the frozen V1 transaction, block, Merkle, difficulty, address, genesis, and P2P wire behavior.

The Go node remains the production-track implementation. The Python tree remains the V1 reference/oracle and is not silently migrated to V2.

## Implemented boundary

- V2 transaction version `2`.
- 64-character lowercase hexadecimal network identity.
- Domain-separated V2 signing and transaction-ID hashing.
- Signature-independent `tx_id`.
- Monotonic sender nonce state beginning at `0`.
- Consensus duplicate-ID rejection during validation and replay.
- V2 nonce-aware mempool and deterministic mining selection.
- V2 GenesisState/network identity binding.
- Fail-closed V2 node startup validation.
- V2 compatibility vectors generated by executable Python reference code.
- V1/V2 protocol separation.

## Compatibility

V1 transactions remain represented by the historical `tx_hash` path. V2 transactions use `version`, `network_id`, `nonce`, and `tx_id`. A V1 transaction cannot validate through the V2 validator, and a V2 transaction cannot validate through the V1 validator.

The P2P wire protocol remains `sayanjali-p2p / 1.0`. V2 identity is carried through the existing HELLO `NetworkName` string; no new HELLO field was added.

## Known limitations

- This phase does not introduce fees, replacement-by-fee, staking, smart contracts, EVM, bridges, governance, validator sets, custody systems, or exchange integrations.
- Mempool persistence is intentionally not implemented.
- Public/mainnet GenesisState and network identity are not approved by this phase.
- Full dependency-backed Go test/build/race/vet execution depends on an environment with access to the existing secp256k1 Go module.
- Independent Python vector generation is included; a second cryptographic implementation should still be run by the release operator on an environment with the Go dependency available.

## Release rule

Do not describe Phase 8.1 as mainnet production-ready solely from source inspection. Final release acceptance requires the real dependency-backed test suite, race test where supported, vector reproduction, ZIP extraction validation, and human diff review.
