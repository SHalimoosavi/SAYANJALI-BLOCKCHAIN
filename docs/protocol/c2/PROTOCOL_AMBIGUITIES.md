**Status:** DESIGN NOT FROZEN — BUILD 2B BLOCKED

## Classification rule

- **NON-CONSENSUS** — does not select or alter consensus behavior.
- **IMPLEMENTATION DETAIL** — can be chosen without changing the protocol, provided the frozen interface/invariants are preserved.
- **CONSENSUS-RELEVANT** — changes state transition, state root, proof validity, activation, or recovery result.
- **BLOCKING** — consensus-relevant ambiguity that permits two competent implementations to produce different consensus state, root, recovery result, or activation behavior.

## Non-blocking observations

1. Current source uses deterministic lexicographic sorting for the legacy root/checkpoint serialization; useful compatibility invariant, not a C-2 tree definition.
2. Current storage calls `Sync()` after each complete record, but this does not define C-2 multi-record atomicity.
3. Existing V2 reorg tests prove current incremental-vs-legacy equivalence; they do not prove future C-2 storage/recovery semantics.

## Audit conclusion

The candidate SMT cryptographic/reference vectors are reproducible, but the protocol boundary around them is incomplete. A-01, A-02, A-03, A-04, A-05, A-06, A-13, A-14, A-15, A-16, A-17, A-18 and A-20 are independently sufficient to block Build 2B.
